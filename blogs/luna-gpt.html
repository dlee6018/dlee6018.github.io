Building GPT from Scratch

January 3, 2026

Over the past few months, I've been working on implementing a transformer language model from scratch. This project has been an incredible learning experience, taking me through the entire machine learning pipeline from architecture design to distributed training. In this post, I'll share some of the key insights and challenges I encountered.

Architecture Overview

The core of the model follows the transformer architecture introduced in "Attention Is All You Need", but with several modern improvements:

  • Multi-head self-attention with scaled dot-product attention
  • RoPE (Rotary Position Embeddings) instead of learned positional encodings
  • FlashAttention for memory-efficient attention computation
  • Layer normalization and residual connections throughout

Multi-Head Attention Implementation

The attention mechanism is the heart of the transformer. Here's a simplified version of the multi-head attention implementation: 

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model, num_heads):
        super().__init__()
        self.d_model = d_model
        self.num_heads = num_heads
        self.d_k = d_model // num_heads
        
        self.W_q = nn.Linear(d_model, d_model)
        self.W_k = nn.Linear(d_model, d_model)
        self.W_v = nn.Linear(d_model, d_model)
        self.W_o = nn.Linear(d_model, d_model)
        
    def forward(self, x, mask=None):
        batch_size, seq_len, d_model = x.size()
        
        # Project to Q, K, V
        Q = self.W_q(x).view(batch_size, seq_len, self.num_heads, self.d_k).transpose(1, 2)
        K = self.W_k(x).view(batch_size, seq_len, self.num_heads, self.d_k).transpose(1, 2)
        V = self.W_v(x).view(batch_size, seq_len, self.num_heads, self.d_k).transpose(1, 2)
        
        # Scaled dot-product attention
        scores = torch.matmul(Q, K.transpose(-2, -1)) / math.sqrt(self.d_k)
        
        if mask is not None:
            scores = scores.masked_fill(mask == 0, -1e9)
        
        attn_weights = F.softmax(scores, dim=-1)
        attn_output = torch.matmul(attn_weights, V)
        
        # Concatenate heads
        attn_output = attn_output.transpose(1, 2).contiguous().view(
            batch_size, seq_len, d_model
        )
        
        return self.W_o(attn_output)

RoPE Positional Embeddings

Instead of learned positional embeddings, I implemented Rotary Position Embeddings (RoPE), which encode relative position information directly into the attention mechanism. This has become the standard for modern language models like LLaMA and GPT-NeoX.

RoPE works by rotating the query and key vectors by an angle that depends on their position: 

def apply_rotary_pos_emb(q, k, cos, sin):
    """Apply rotary position embedding to query and key tensors."""
    def rotate_half(x):
        x1, x2 = x.chunk(2, dim=-1)
        return torch.cat([-x2, x1], dim=-1)
    
    cos = cos.unsqueeze(1)  # [seq_len, 1, d_head]
    sin = sin.unsqueeze(1)
    
    q_embed = (q * cos) + (rotate_half(q) * sin)
    k_embed = (k * cos) + (rotate_half(k) * sin)
    
    return q_embed, k_embed

Training Pipeline

Building the model was only half the battle. I implemented a complete training pipeline with three stages:

1. Pretraining

Large-scale pretraining on a diverse corpus of text data. This stage teaches the model general language understanding and generation capabilities.

2. Supervised Fine-Tuning (SFT)

Fine-tuning on instruction-following datasets to make the model more helpful and aligned with user intent.

3. Direct Preference Optimization (DPO)

Post-training using DPO to further align the model with human preferences without requiring a separate reward model. This was particularly interesting because I studied how DPO behaves in low-data, small-model regimes.

Distributed Training

Training large language models requires multiple GPUs. I implemented multi-GPU training using PyTorch's Distributed Data Parallel (DDP): 

def setup_ddp():
    torch.distributed.init_process_group(backend='nccl')
    local_rank = int(os.environ['LOCAL_RANK'])
    torch.cuda.set_device(local_rank)
    
    model = TransformerModel(config).to(local_rank)
    model = DDP(model, device_ids=[local_rank])
    
    return model, local_rank

Key challenges included:

  • Gradient synchronization across GPUs
  • Efficient distributed data loading
  • Handling variable sequence lengths with padding
  • Monitoring training metrics across processes

Key Learnings

This project taught me a lot about the practical challenges of training language models:

  • KL regularization is crucial in RL-based post-training to prevent the model from deviating too far from the base model
  • Reward model design requires careful thought about what signals to optimize for
  • Optimization stability becomes a major concern in low-data regimes where standard techniques may not apply
  • Memory efficiency is paramount - FlashAttention was essential for training longer sequences

Future Work

There's still much to explore. I'm particularly interested in:

  • Experimenting with different attention mechanisms (e.g., grouped query attention)
  • Implementing more sophisticated post-training techniques
  • Scaling to larger model sizes and datasets
  • Better understanding the dynamics of preference learning

Building this from scratch has given me a deep appreciation for the engineering and research that goes into modern language models. Every component, from the attention mechanism to the distributed training infrastructure, requires careful design and implementation.
